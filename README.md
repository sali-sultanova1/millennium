# Миллениум

Сайт туристического агентства с собственным каталогом и кабинетом для сотрудников. Менеджеры добавляют предложения агентства, обновляют цены и фотографии и публикуют туры на сайте. Посетитель может сравнить несколько вариантов и отправить их одной заявкой. Менеджер получит контакты клиента и выбранные предложения в кабинете.

Дипломный проект по разработке веб-приложений на Python в Компьютерной Академии ТОП.

[Демоверсия на Render](https://millennium-demo.onrender.com/)

## Возможности

| Роль | Что можно делать |
| --- | --- |
| Посетитель | Искать и сравнивать туры, сохранять варианты в избранном без регистрации. Оставлять заявку на отдельный тур, отправлять подборку или описывать пожелания к поездке. |
| Менеджер | Управлять направлениями и турами, обрабатывать заявки и редактировать свой профиль. Входить в кабинет по логину или электронной почте. |
| Владелец | Выполнять задачи менеджера, добавлять сотрудников, редактировать их данные и управлять доступом к кабинету. При отключении доступа действующие сеансы сотрудника завершаются. |

- **Поиск на сайте.** Туры можно отфильтровать по направлению, городу вылета, периоду, длительности, питанию и цене. При сравнении цен учитываются валюта и расчёт на человека или на всю поездку.
- **Работа с каталогом.** В кабинете можно найти тур по названию, курорту или отелю и отфильтровать список по направлению и статусу. Черновик можно дополнять до публикации. Порядок загруженных снимков определяет, какое фото станет обложкой.
- **Работа с заявками.** В кабинете есть вкладки «Новые», «В работе», «Архив» и фильтр «Только мои». О новых обращениях сообщает индикатор в меню. При включённом SMTP сайт также отправляет письма сотрудникам.

## Как проходит заявка

1. Клиент добавляет туры в избранное и нажимает «Обсудить выбранные туры».
2. Заявка появляется в кабинете со статусом «Новая». Вместе с контактами сохраняются выбранные туры и их условия на момент отправки.
3. Менеджер нажимает «Взять в работу». Система назначает ответственного и переводит заявку в статус «В работе».
4. После общения с клиентом менеджер завершает заявку. Она попадает в архив со статусом «Завершена».

Если агентство обновит цену в каталоге, в заявке будет доступна цена на момент отправки. Заявка и выбранные туры сохраняются в одной транзакции. Если два сотрудника одновременно попытаются взять одну заявку, ответственного назначит первый успешный запрос.

## Локальный запуск

Понадобятся Git и Docker с Docker Compose. На macOS можно использовать Docker Desktop. Команды ниже рассчитаны на новую локальную копию проекта.

```bash
git clone https://github.com/sali-sultanova1/millennium.git
cd millennium
cp .env.example .env
docker compose up -d --build
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```

| Страница | Локальный адрес |
| --- | --- |
| Главная | [127.0.0.1:8000](http://127.0.0.1:8000/) |
| Каталог | [127.0.0.1:8000/tours/](http://127.0.0.1:8000/tours/) |
| Кабинет сотрудников | [127.0.0.1:8000/manager/](http://127.0.0.1:8000/manager/) |
| Администрирование Django | [127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/) |

### Первая проверка сайта

1. Войди в кабинет с учётной записью, созданной через `createsuperuser`. Добавь направление и включи его показ на сайте.
2. Создай тур с будущей датой вылета и фотографиями. Сохрани черновик, затем нажми «Опубликовать» в списке туров.
3. Открой карточку нового тура в каталоге, отправь тестовую заявку и найди её во вкладке «Новые» в кабинете.

Чтобы проверить работу кабинета под ролью менеджера, добавь отдельную учётную запись в разделе «Сотрудники». Группа «Менеджеры» и её права настраиваются при применении миграций.

Если локальный сайт не открывается, проверь состояние контейнеров и последние сообщения приложения и базы.

```bash
docker compose ps
docker compose logs --tail=50 web db
```

После работы контейнеры можно остановить командой `docker compose stop`.

## Настройки окружения

При локальном запуске с настройками из [`.env.example`](.env.example) база и фотографии хранятся в томах Docker `postgres_data` и `media_data`. Пароли и ключи задаются в локальном или серверном `.env`. Хранилище Yandex Object Storage и почтовые уведомления подключаются при необходимости.

| Возможность | Настройка |
| --- | --- |
| Хранить фотографии в Yandex Object Storage | Установить `MEDIA_USE_S3=True` и заполнить переменные `MEDIA_S3_*`. |
| Отправлять уведомления о новых заявках | Установить `INQUIRY_NOTIFICATIONS_ENABLED=True`, указать адрес сайта в `INQUIRY_NOTIFICATION_BASE_URL` и заполнить настройки `EMAIL_*` для своего SMTP-провайдера. |

Уведомления отправляются на адреса из профилей активных менеджеров и администраторов. В письме есть ссылка на заявку в кабинете. [Локальная проверка через вывод писем в логи](docs/testing.md#проверка-уведомления).

## Тестирование

Команды запускаются из папки проекта при работающих контейнерах.

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test
```

При отправке коммитов и открытии pull request [GitHub Actions](.github/workflows/ci.yml) собирает образ, проверяет код Ruff, запускает PostgreSQL и выполняет проверки Django, миграций и тесты.
