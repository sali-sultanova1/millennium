# Тестирование

## Автоматические проверки

Команды выполняются из папки проекта после [локального запуска](../README.md#локальный-запуск).

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test
```

| Набор | Примеры проверок |
| --- | --- |
| [Каталог](../catalog/tests.py) | Видимость черновиков, фильтрация по датам и ценам, порядок фотографий и валидация стоимости. |
| [Заявки](../inquiries/tests.py) | Отправка двух туров одной заявкой, сохранение исходных условий, откат при ошибке записи и сохранение заявки при сбое почты. |
| [Кабинет](../manager/tests.py) | Поиск туров, создание сотрудника, вход по логину и почте, отключение сеансов и обновление индикатора заявок. |
| [Страницы агентства](../pages/tests.py) | Навигация, контакты и переход из списка направлений в каталог. |

При `push` и `pull_request` [GitHub Actions](../.github/workflows/ci.yml) собирает образ, запускает Ruff, поднимает PostgreSQL и выполняет проверки Django, миграций и тесты.

## Проверка в браузере

Используйте локальную базу и тестовые контактные данные.

1. Создайте активное направление и два тура с будущими датами вылета. До публикации проверьте, что их нет в каталоге. Опубликуйте оба тура.
2. Измените порядок двух фотографий у одного тура. В каталоге должна появиться новая обложка.
3. Добавьте оба тура в избранное и отправьте их одной заявкой. В кабинете откройте заявку и проверьте, что она содержит оба предложения.
4. Измените цену одного тура. В каталоге должна отображаться новая цена, а в уже отправленной заявке — исходная.
5. Возьмите заявку в работу и проверьте статус и имя ответственного. Нажмите «Завершить заявку» и найдите её в архиве.

### Проверка уведомления

Задайте в `.env` следующие значения.

```dotenv
INQUIRY_NOTIFICATIONS_ENABLED=True
INQUIRY_NOTIFICATION_BASE_URL=http://127.0.0.1:8000
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
```

Укажите тестовый адрес в профиле активного менеджера или администратора. Затем примените настройки и откройте логи.

```bash
docker compose up -d web
docker compose logs -f web
```

Отправьте новую заявку. В логах должно появиться письмо с номером и ссылкой на кабинет. Консольный бэкенд выводит письмо в логи, поэтому для этой проверки доступ к почтовому ящику не нужен.
